# ADR 0003: Диагностика в ограниченном дочернем процессе

## Контекст
Сетевой вызов или синхронное разрешение имени могут зависнуть. Диагностика не должна блокировать UI и lifecycle, публиковать устаревшие результаты либо обходить защиту.

## Решение
Выполнять сетевые проверки одним выделенным завершаемым дочерним процессом с единственным активным запуском. Открывать запросы только после привязки процесса к Job; держать владение до подтверждённого завершения. При отмене, смене контекста, закрытии или release прекращать запуск и запрещать публикацию устаревшего результата. Release снимает политику только после подтверждённого выхода процесса.

## Почему
Обычный поток с socket timeout не ограничивает все возможные зависания и не даёт надёжно остановить сетевую работу. Освобождение защиты при неподтверждённом завершении оставило бы дочерний процесс работать после снятия политики.

## Последствия
Один зависший запуск не накапливает новые проверки; UI и lifecycle остаются ограниченными по времени. Если выход процесса подтвердить нельзя, release отклоняется, а защита сохраняется до безопасного завершения.
