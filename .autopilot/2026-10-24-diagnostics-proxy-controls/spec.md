# Спецификация: диагностика и управление прокси

## Задача
Добавить три выбранные функции в существующий KROTTUN: диагностику одной кнопкой, редактирование прокси и управление резервами. Сохранить существующий интерфейс, карту, mesh, терминал «Синий лёд», блок защиты и фиксированное окно 520×760.

## Редактирование (R02)
Кнопка редактирования в строке сервера открывает форму с названием, хостом, портом, протоколом SOCKS5/HTTP, логином и новым паролем. Сохраняется тот же id и ссылки на сервер. Пароль никогда не загружается в DOM: пустое поле оставляет прежний пароль, отдельный флаг явно удаляет его. Значения нового пароля не обрезаются. Изменение endpoint/auth сбрасывает устаревшие ping/geo/status и hostname cache; фоновое гео не должно переписать изменённый сервер старым ответом.
Редактирование доступно в IDLE/ERROR и RUNNING: сохранённая запись заменяется копией, активный runtime и неизменяемый снимок текущей сессии не меняются. При работающем туннеле форма явно говорит «Применится при следующем подключении». При сохранённой блокировке разрешается исправить сохранённый сервер, без автоматического подключения или снятия защиты; hostname-bound cache очищается при изменении адреса. В STARTING/STOPPING и во время release редактирование отклоняется с понятной ошибкой. Неизвестный id, неверные поля, дубликаты отправки и сбой сохранения обрабатываются; при сбое диска прежние данные остаются. В форме ошибки не сбрасывают введённые поля. Название отображается в списке и карточке выбранного сервера.

## Резервы (R03)
Отдельное модальное окно «Резервы»: список сохранённых серверов, включение/исключение, кнопки вверх/вниз. Основной сервер всегда выбран пользователем и идёт первым; резервный список применяется после него, основной исключается из повторов. Пустая очередь явно означает «без резервов», при отказе остаётся блокировка. Первое открытие старого хранилища сохраняет прежнюю семантику: все имеющиеся серверы в прежнем порядке; после явного сохранения новые серверы автоматически не включаются.
Хранить упорядоченные id в settings, без копий credentials. Удалённые/дублирующиеся id нормализуются; неизвестные id при записи отклоняются. Сбой записи откатывает память. Изменение очереди при работающем туннеле относится к следующему ручному подключению, о чём говорит UI. На каждое ручное подключение фиксируется неизменяемый снимок копий primary + reserves. Начальный запуск и watchdog используют одну очередь сессии; watchdog не обращается к «всем остальным», не добавляет исключённые или новые серверы и не меняет основной выбор. При последовательных отказах нельзя зациклиться между уже исчерпанными кандидатами; exhaustion сохраняет защиту и требует ручного повтора. Пересоздание рабочего ядра, отмена и release сохраняют прежние гарантии.

## Диагностика (R01)
Одна кнопка открывает компактное модальное окно и запускает проверку. Пять отдельных строк: прокси/туннель, DNS, HTTPS, внешний IP, системный прокси Windows. Состояния running/pass/fail/warning/skipped, русские пояснения и конкретная рекомендация при сбое. Сетевой timeout не называется доказательством утечки. Отчёт существует только в памяти; разрешено показать валидированный внешний IP внутри результата, без сохранения в журналы/файлы.
При здоровом protected TUN проверки идут по системной маршрутизации через него, trust_env=False, allow_redirects=False. Прокси/туннель проверяется по существующему runtime health и результатам HTTPS, без прямого Python-сокета к endpoint. DNS — фактический системный getaddrinfo для example.com, HTTPS — фиксированный https://example.com, IP — фиксированный https://api.ipify.org?format=json с валидацией адреса. В unarmed/IDLE без работающего ядра диагностируется выбранный сохранённый прокси: TCP-доступность его endpoint; DNS через фиксированный HTTPS DoH-запрос cloudflare-dns.com/dns-query (example.com, type=A, JSON) через этот прокси; HTTPS и IP через этот же явный proxy transport. Не наследовать Windows/env proxy, не делать direct fallback. DNS-строка явно говорит «DNS через прокси (DoH)» и не выдаёт это за проверку системного DNS. Нет выбранного сервера — skipped. При blocked/unknown/переходах сетевые строки честно skipped с предложением подключиться; диагностике запрещено самостоятельно подключать/останавливать/снимать защиту или делать прямые внешние пробы. Это диагностика активного подключения либо одного выбранного прокси до включения защиты, не массовый тест списка. Snapshot выбранного proxy передаётся worker только в памяти; credentials не возвращаются и не логируются.
Флаг системного прокси только читается; включённый флаг даёт warning о возможном конфликте, недоступное чтение — skipped/unknown, не ложный pass. Не передавать настройки endpoint из реестра. Никаких raw exception, proxy URLs/credentials и автоматических исправлений.
Все сетевые операции в одном killable spawn worker: один экземпляр, hard deadline всего запуска не более 12 секунд, запрет накопления после зависания, job binding перед открытием request gate (существующий Windows Job механизм), владение до подтверждённого exit. Смена поколения, process, отмена, release, закрытие запрещает публикацию устаревшего результата и прекращает worker. Завершение UI bounded даже при зависшем bridge RPC. Результаты и их опрос не блокируют lifecycle locks и не вмешиваются в manager probe worker.

## Доставка (R04)
Autopilot: манифест, спецификация, таски, независимые coverage/review и слепая приёмка в чистом клоне. Детерминированные offline-тесты с fake network/process/storage; существующий полный suite должен пройти. Изолированный browser rendering production HTML с fake pywebview, без запуска настоящего приложения и сетевых проб. Пересобрать EXE в dist/proxy-controls/KROTTUN.exe, проверить состав embedded assets и версию; не запускать EXE. Все новые коммиты только pu-pu-puu <282508417+pu-pu-puu@users.noreply.github.com>, без push/release.

## Решения по реализации
Существующий Python/pywebview/sing-box, стандартная библиотека и уже установленные requests/PySocks; новых зависимостей нет. Границы в interfaces.md. Модальные окна прокручиваются внутри фиксированного окна, без resize API, пользовательские значения только textContent/value. Для UI использовать существующие цвета, CSS и SVG whitelist; не перерисовывать приложение.
Три плотных последовательных таска: редактирование, резервы, диагностика и доставка. Калибровка T2 сокращена до трёх: все функции пересекаются в одном bridge и одном HTML; дополнительное дробление создаст лишние границы.
