## Что должно заработать
Пользователь редактирует сохранённый сервер без удаления, с сохранением его id и безопасным обращением с паролем.

## Разделы спецификации
Редактирование (R02); общие ограничения Решения по реализации и Доставка (R04). interfaces.md и notes.md читать первыми.

## Критерии приёмки
- [ ] Форма редактирования доступна из строки, безопасные поля заполнены, имя видно в карточке и списке; id сохраняется.
- [ ] Пустой новый пароль сохраняет прежний; явное удаление работает; пароль никогда не возвращается API, поле очищается при закрытии.
- [ ] Валидация/неизвестный id/сбой сохранения оставляют прежние данные и введённые поля; специальные символы не становятся HTML.
- [ ] Lifecycle STARTING/STOPPING/release запрещает edit на backend; IDLE/ERROR и RUNNING позволяют, без рестарта/изменения WFP. RUNNING edit меняет только сохранённую запись, UI объясняет применение при следующем подключении; runtime неизменен; интеграционная проверка неизменяемого session snapshot относится к таску 02, где snapshot появляется.
- [ ] Смена адреса сбрасывает старые гео/latency/status/cache; старый async geo результат не переписывает новую запись.
- [ ] Новые offline-тесты демонстрируют RED до реализации, полный suite зелёный; без новых зависимостей.
